Why `defaults.json` sets what it sets (a sibling file because GSD copies every key of the file into each new project's `.planning/config.json`, so a `_doc` key inside it would land in every project's config).

`~/.gsd/defaults.json` is a copy of `config/gsd/defaults.json`, made by `scripts/sync/sync_gsd_runtime.py --apply`. GSD reads it in `buildNewProjectConfig` (`get-shit-done/bin/lib/config.cjs`) when it creates a project's `.planning/config.json`, merged under the user's choices; a nested `workflow` object is accepted.

A copy and not a link because GSD writes that file (read in the installed GSD): the settings workflow's "save as global defaults" (`workflows/settings.md:393-399`) has the agent write `~/.gsd/defaults.json`, which through a link would overwrite forge's tracked file; `config.cjs:148` also rewrites it, by temp file and rename, but only to migrate a deprecated `depth` key. A real file there that differs from forge's is the user's choice (the settings workflow writes it on purpose): it is left alone and reported as one plain line, with no `!`, exit 0 and 0 changes. Delete it to let the next sync copy forge's, or move what it holds into `config/gsd/defaults.json`. The same applies after forge edits this file: every existing copy then differs, and stays as it is, until it is deleted.

`workflow.ui_phase` and `workflow.ui_safety_gate` are false: GSD's UI design contract (`UI-SPEC.md`) is off by default in every project. design-taste, impeccable, ui-typography and each project's own components and tokens already cover that ground, and plan-phase's step 5.6 gate fires on nearly every frontend phase. That gate is skipped only when both keys are false. `ui_phase` alone also drives two other workflows (read in the installed GSD): `autonomous.md` generates a UI-SPEC for every frontend phase while it is not false, and `verify-work.md` runs its Playwright UI check only when it is true or a UI-SPEC exists. So false is the only value that is actually off.

Using the contract in a project that has it off: `/gsd-ui-phase N` exits with "UI phase is disabled in config" while `workflow.ui_phase` is false (`ui-phase.md` step 1), so set it first: `gsd-sdk query config-set workflow.ui_phase true`, or `/gsd-config`. Setting only `ui_phase` true leaves the plan-phase gate silent (it blocks only when `ui_safety_gate` is true and no UI-SPEC exists) but lets autonomous generate specs again; set both to true to get the whole contract back. This file seeds new projects only; an existing project keeps what its own `.planning/config.json` says.
