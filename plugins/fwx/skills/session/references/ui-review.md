# Reviewing the fixes of a UI walk

Step 8 of `SKILL.md` sends you here when the part had a UI walk. A button press is not enough reason to undo code, so a rejection is only recorded and asked about.

1. `fwx walk review-page --run <run> --fixed <file>` builds an item per fix (before, after, finding) and per `CONTRADICTED` finding left unfixed; with `"items": 0`, skip this file. `python3 <paths.verdict> verdict <review dir>` builds the page and tries to open it. If its output holds a `NOT OPENED` or `xdg-open` line, put it in your message in its own code block: the owner does not see tool output. Say in one line that the page is ready and end your turn. With no `paths.verdict`, number the items in the chat, each screenshot's open line given the same way; he answers by number with ok, redo or not defect and a reason for the last two, which you read as the lists of step 2.
2. He pastes the text of `Copy answers`. Save it with `mktemp`, run `fwx walk review-answers --run <run> <file>`, remove it. It only sorts the answers (it writes `review/answers.json` and no decision) and prints `{accepted, redo, not_defect, contradicted_wanted, open, stale, missing_note}`: `redo` is "the fix does not work, fix it again", `not_defect` is "this is not a defect", each a list of `{id, note, commit}`; those two are the rejections. For each id in `open` ask for what is missing, his answer or a rejection's reason: a revert rests on it, so do not guess it. Name any `stale` id to him and drop it.
3. Give each note word for word to the `decisions` agent, `source` starting `ui-walk review`. `not_defect`: `support` `approved`, so the next walk treats the same finding as `CONTRADICTED`. `redo`: `support` `chosen`; the finding stays valid, so the next walk may propose it again.
4. An id of `contradicted_wanted` is a change of intention: step 7. With a rejection, stop and ask once before touching anything, as a numbered list: per rejected fix, what reverting undoes (its commit, from the `--fixed` file) and "revert it?", and per `redo` also "another fix round?".
5. Run only what his words ask for, by the numbers he names. Stage `executing` with `part <N> corrections`. A revert: `fwx wave prepare ... --revert <ids>`, which launches nothing. A fix round: his `redo` notes as findings (the recipe at the end of step 5 of `SKILL.md`, `claim` his note), `fwx rounds <part> --reset "<his reasons>"`, `fwx wave prepare ... --fix <file>`, `fwx:execute`; a revert comes first when he asks for both. Then stage `reviewing`.

Then continue step 8 after the line that sent you here.
