# Closing a phase

You do these five steps in this order, after the last part's review. There is no closing conversation: the reports are written and the owner has read them. `<branch>` is the phase branch; `<default>` is `project.default_branch` of `.claude/fwx.json`.

1. **Land.** List the agents you launched that still run and stop those that work in the phase worktree: nothing may write to it while you push. Then:
   - With `origin` on GitHub: `git push origin <branch>` from the worktree, then `gh pr create --base <default>` with a body of four sections, `## Why`, `## What changed`, `## Scope` (what the phase left out: `not_built` and `later` of `plan.md`) and `## Verification` (the evidence line of the last report: commit, command, exit code). For a job retaken from the factory the pull request already exists against the factory branch: the push updates it and you open no other.
   - Without `origin`: the branch stays where it is. Give the owner the command that merges it into `<default>`, as one line to paste, and do not run it: merging into the default branch is his.
   - Never push to `<default>` or to a branch in `production.branches`, because a merge there ships to users without his review. A deploy (`production.commands`) is run only through the consent window, which asks him: a "no" is reported once and not retried, because the owner has refused it. A push that fails is reported with git's message and you stop: a force push could discard work on the remote.
2. **A retaken job.** For an issue taken from Linear, ask "close `<KEY>` when this merges?". On yes, `Fixes <KEY>` goes in the pull request body (an existing one: append it with `gh pr edit`): Linear then moves the issue when the owner merges, and the client cannot edit issues. Then post the summary and the pull request link: `fwx linear comment <KEY> --kind result`, body on stdin.
3. **Stage.** `fwx stage <phase folder> closed`, then commit `.fwx/` (rule 4 of `SKILL.md`).
4. **Cleanup.** After a UI walk, run `fwx walk stop --orphans`. The phase worktree stays: its pull request is not merged yet, and a worktree is removed only once its pull request is merged and nothing in it is unsaved. Step 0 of `SKILL.md` removes it at the start of a later session. Say in one line that it stays and its path.
5. **Next.** When `fwx phase list --json` shows no open phase in the milestone, say in one line what could come next: a new milestone or the next topic. Otherwise say nothing.
