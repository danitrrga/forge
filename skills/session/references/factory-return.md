# Retaking a job the factory returned

`retake <KEY>`: the owner chose an issue the factory handed back as `needs-owner` or `failed`. You carry it through the steps of `SKILL.md`, but the phase starts from the factory's work and not from a discuss. `<job>` below is `.fwx/factory/<KEY>/` as it is in that branch.

1. **Resolve and find the branch.** Run `fwx state resolve --json` first: it gives `main_checkout` and `plan_root`, which the rules and steps of `SKILL.md` need. Run `git fetch origin`, then `git branch -a --list "*/factory-<KEY>" "*/factory-<KEY>-a*"`: the branch is `factory-<KEY>`, or `factory-<KEY>-aN` with the highest N (the pattern leaves out another key that ends the same way). Read it through its `origin/` name in `git show`. No branch: say so and stop. `<base>` is `git merge-base <branch> <factory branch>`, the factory branch being `project.factory_branch` of `.claude/fwx.json`.
2. **Read why it came back.** `git show <branch>:<job>/state.md`, and the last `stage` rows of `git show <branch>:<job>/audit.tsv`. Tell the owner in a few lines what the factory tried and why it stopped, and ask what he decides about that reason: a numbered question, no recommendation (rule 6).
3. **Make the phase.** `fwx state new-phase <KEY in lower case>` (add `--subproject` for a subproject's job). Copy by command, not by retyping: `git show <branch>:<job>/plan.md > <phase folder>/plan.md`, and the same for `context.md` when the job has one; without it, write `context.md` by hand from the issue and the owner's answer, the one exception to the rule on `.fwx/`. No `fwx` command reads a Linear issue: take its text from the `linear-forge` tools when the project has them, else ask the owner to paste it. The `decisions` agent records his answer (`source` `factory return <KEY>`).
4. **Record the reused stages.** The stage table has no step from `discuss` to `postmortem`, so write `fwx stage <phase folder> premortem --why "reused from factory <KEY>"` and then `fwx stage <phase folder> planning --why "reused from factory <KEY>"`.
5. **Post-mortem, structural.** Go to step 3 of `SKILL.md`, and call `fwx:post-mortem` with `<phase folder>; language: <language>; structural <base>..<branch>`: the review looks at the plan and the work at the level of structure.
6. **Execute on the job's branch.** In step 4 the phase branch is `<branch>` itself: make the worktree from it, with `git worktree add <main_checkout>/.claude/worktrees/<name> <branch>` and no `-b`, and write stage `executing` with `part 1 branch <branch>`. The job is one part. Steps 5 to 8 run as written; the close (`references/closing.md`) lands on the pull request that exists against the factory branch.
